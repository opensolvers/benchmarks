----- Caveat -----
RVV.h stores double4_t as alignas(32) double[4] (GCC cannot put RVV types in
structs). Each operator+/−/* and load/store path does vle → compute → vse via
the POD buffer, so values do not stay in vector registers across expression
trees. This microbench therefore A/Bs the *simd layer path*, not a hand-kept
vfloat64m2_t kernel. FORCE_SCALAR wins ~2.65× here; a true RVV win would need
keeping vectors live (or a different API).

Both binaries use the same -march=rv64gcv, so GCC may auto-vec parts of the
Scalar.h path — that is intentional (same ISA flags, different simd backend).
